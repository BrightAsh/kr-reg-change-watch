# 한국 규제 변경 모니터

법령, 고시·공고, 지침·행정규칙, 입법예고, 행정예고, 정책자료, 뉴스 보조 자료를 자동으로 수집해 날짜별로 보여주는 규제 변경 모니터링 앱입니다. 사용자는 캘린더에서 날짜를 선택하고, 기관·출처·문서유형·변경유형 필터로 필요한 자료를 빠르게 확인할 수 있습니다.

서비스 페이지: https://brightash.github.io/kr-reg-change-watch/

## 앱 소개

이 앱은 일하는 사람이 “오늘 어떤 규제성 변경이 있었는지”를 한 화면에서 확인하기 위한 업무용 모니터링 도구입니다.

주요 기능은 다음과 같습니다.

| 기능 | 설명 |
| --- | --- |
| 날짜별 조회 | 캘린더에서 날짜를 선택하면 해당 일자에 수집된 자료만 보여줍니다. |
| 자동 분류 | 수집 자료를 법령, 고시/공고, 지침/규칙, 뉴스/발언으로 분류합니다. |
| 공공기관 체계 탭 | 공공기관 운영 법령 및 정부지침 체계 9개 항목에 해당하는 자료만 별도 탭에서 확인합니다. |
| 필터와 검색 | 기관, 출처, 문서유형, 변경유형, 검색어로 자료를 좁혀 봅니다. |
| 상세 화면 | 각 항목의 원문 링크, 기본 정보, 수집 본문, 첨부 링크를 확인합니다. |
| AI 브리핑 | 사용자가 AI 모델과 키를 설정하면 현재 목록 전체를 업무용 브리핑으로 요약합니다. |
| AI 요약 | 상세 화면에서 수집 본문을 기준으로 개별 항목을 요약합니다. |

## 앱 환경과 운영 방식

| 항목 | 내용 |
| --- | --- |
| 웹사이트 배포 | GitHub Pages로 정적 웹사이트를 배포합니다. |
| 자동 수집 | GitHub Actions가 매일 한국시간 0시 기준으로 자동 실행됩니다. |
| 수집 방식 | 공식 Open API, 공공데이터 API, RSS, 정부 부처 게시판 HTML 수집, ALIO 자료 수집을 함께 사용합니다. |
| 데이터 관리 | 수집 결과는 날짜별 JSON 데이터로 정리되어 화면에서 바로 조회됩니다. |
| 캐시 방식 | 이미 해당 날짜 자료가 있으면 기존 데이터를 우선 보여주고, 강제 수집 시 새로 수집합니다. |
| 사용자 화면 | 별도 로그인 없이 GitHub Pages 웹사이트에서 조회할 수 있습니다. |

## 공공기관 운영 법령 및 정부지침 체계

앱은 전체 수집 자료와 별도로 다음 9개 항목에 해당하는 자료를 필터링합니다. 직접 규정명 또는 하위/위임 규정명이 제목·요약·출처 정보에서 확인되면 높은 신뢰도로 분류하고, 정책자료는 제목·요약의 강한 문구가 맞는 경우에만 후보로 분류합니다.

| 번호 | 항목 | 직접/하위 기준 |
| --- | --- | --- |
| 1 | 공기업·준정부기관 계약사무규칙 | 계약사무규칙 |
| 2 | 공기업·준정부기관 회계사무규칙 | 회계사무규칙, 회계기준 |
| 3 | 공기업·준정부기관 사업 예비타당성조사 운용지침 | 예비타당성조사 운용지침 |
| 4 | 공기업·준정부기관 총사업비관리지침 | 총사업비관리지침 |
| 5 | 공기업·준정부기관의 경영에 관한 지침 | 경영에 관한 지침, 예산운용지침, 감사 운영 규정 |
| 6 | 공공기관의 혁신에 관한 지침 | 혁신에 관한 지침, 공공기관 혁신 |
| 7 | 공공기관의 통합공시에 관한 기준 | 통합공시 기준, 경영정보 공시 |
| 8 | 공공기관의 안전관리에 관한 지침 | 안전관리 지침, 안전관리등급제 |
| 9 | 공기업·준정부기관 임원 보수지침 | 임원 보수지침 |

## AI 모델 사용

AI 기능은 사용자가 모델 제공자와 API 키를 직접 입력했을 때만 동작합니다. 한 번 키를 저장하면 같은 브라우저에서 다음부터는 저장된 모델과 키를 확인한 뒤 AI 브리핑 또는 AI 요약을 진행할 수 있습니다.

선택 가능한 모델 제공자는 Gemini, Groq, OpenRouter, OpenAI입니다.

| 기능 | 입력 자료 | 결과 | 비용 |
| --- | --- | --- | --- |
| AI 브리핑 | 현재 화면에 표시된 여러 항목의 제목, 기관, 날짜, 본문 일부 | 선택 날짜 또는 필터 결과 전체를 업무용 브리핑으로 요약 | 선택한 모델 제공자의 정책에 따라 무료 한도 또는 비용 발생 |
| AI 요약 | 상세 화면의 수집 본문 | 개별 항목의 핵심 내용, 적용 대상, 확인할 업무 영향을 요약 | 선택한 모델 제공자의 정책에 따라 무료 한도 또는 비용 발생 |

AI 요약은 현재 앱이 이미 수집한 본문, 수집 메타데이터 JSON, 원문 URL, 첨부 URL을 함께 전달해 동작합니다. 원문 URL을 AI가 직접 웹 검색해서 읽는 방식은 기본 동작이 아니며, URL은 사용자가 공식 원문을 확인할 수 있는 링크로 함께 제시됩니다. 원문 본문을 더 많이 확보할수록 AI 요약 품질도 좋아집니다.

API 키는 사용자의 브라우저에 저장됩니다. 공용 PC에서는 사용 후 앱 화면에서 키를 삭제하는 것이 좋습니다.

## 메일 알림

메인 화면 오른쪽 위의 `일일 알림 받기` 버튼에서 받을 이메일, 탭, 항목, 추가 필터를 고르면 Google Apps Script Web App이 Google Sheet에 구독 정보를 저장합니다. 매일 자동 수집이 끝나면 GitHub Actions가 같은 구독 목록을 읽어, 사용자별 필터 조건에 맞는 자료만 Gmail SMTP로 발송합니다.

화면에서 `아이디 확인`을 먼저 눌러야 수신 신청 또는 수신 중지를 할 수 있습니다. 이미 등록된 이메일이면 저장된 필터를 불러와 수정할 수 있고, 등록되지 않은 이메일이면 새 수신 신청을 할 수 있습니다.

구독 저장소에는 수신 이메일, 활성 상태, 선택 탭과 항목, 추가 필터, 등록·수정·수신중지 시간이 저장됩니다. 전체 구독자 목록 조회는 별도 읽기 토큰을 요구하도록 분리해 GitHub Actions만 읽을 수 있게 했고, 홈페이지에서는 개별 이메일 확인, 수신 신청, 수신 중지만 호출합니다.

발신 계정 정보와 외부 저장소 연결 정보는 GitHub Actions의 비공개 설정으로 관리합니다. Google Sheet에는 발신 계정이나 앱 비밀번호가 저장되지 않고, 수신 이메일과 필터 정보만 저장됩니다.

수동 테스트는 GitHub Actions의 `Email alert test` 워크플로로 특정 날짜를 강제 수집한 뒤 실제 메일 발송까지 확인합니다. 평소에는 매일 자동 수집이 끝난 뒤 같은 발송 흐름이 자동으로 실행됩니다.

현재 구현은 이메일 소유 확인 링크를 보내는 방식은 아닙니다. 즉, 누군가 다른 사람의 이메일을 입력할 수 있습니다. 공개 서비스로 운영할 때는 최초 등록 시 확인 메일 링크를 클릭해야 활성화되는 절차를 추가하는 것이 좋습니다.
